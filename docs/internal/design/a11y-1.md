# Accessibility pass 1 (prep for lane A's A11y card)

_Design session, 3 Nov 2026. Current `main` (v0.9.95.1) served locally, Chromium 1366×768, English. Tools:
**axe-core 4.10.2** (rules wcag2a, wcag2aa, wcag21aa, best-practice) on home, join, empty room, playing room (video
file), ⚙️ settings, invite, ⋯ More, games hall, XOX, voice; a scripted **keyboard walk** (Tab through each screen,
recording order, visible focus ring, whether focus enters / stays in / returns from dialogs, Esc); **target sizes**
(< 24 px); **reduced motion** (`prefers-reduced-motion: reduce`, looking for running infinite animations). Not
covered: a real screen reader (NVDA / VoiceOver) pass, the film page, phones; those are the owner's hand test or a
later pass._

## Keyboard
| # | Where | What | Suggested fix |
|---|---|---|---|
| K1 | Room, every screen | **Tab order starts in the middle and the top bar comes last.** Order: link box → Search → Add → Play now → (video) → Together → chat → footer → first tips → *then* logo, room name, Invite, ⋯ More, Extension, Profile, Settings. A keyboard user reaches Invite only after the footer. | Put the top bar first in the DOM (or `order` via CSS only, never `tabindex`), so the order is top bar → link box → video + rail → Together → tabs → chat → footer. Add a "Skip to the video" link as the first stop. |
| K2 | Playing room (video file; same for YouTube) | **The rail can't be reached by keyboard.** The walk went from the video's own controls straight to "Together"; the rail's buttons (React, Pin, Games, Join voice, Camera, More, Fullscreen) never got focus while the rail rests (edge mode keeps it out of the tab order). Keyboard users lose speed, sync, next, games and fullscreen (some have shortcuts, but not all). | When focus comes after the video, show the rail (`:focus-within` keeps it out; today's `tabbing` flag already exists) and keep its buttons in the tab order right after the player. |
| K3 | ⋯ More menu | Opening it with Enter **leaves focus on the ⋯ button**; Tab goes back into the page, not through the menu items; Esc closes but focus doesn't return to ⋯. | On open, focus the first `menuitem`; ↑ / ↓ move, Home / End jump, Tab / Esc close and return focus to ⋯ (the WAI-ARIA menu button pattern). Same for the games hall (`#game-menu`, `role=menu`). |
| K4 | ⚙️ Settings and 🔗 Invite dialogs | Focus moves into the dialog (good) and Esc closes it (good), but **Tab leaves the dialog**: 10 of 15 (settings) and 13 of 15 (invite) Tab presses landed behind it. After Esc, focus returns to ⚙️ (good) but **not to 🔗 Invite**. | Trap focus inside every `.dialog-backdrop` dialog (first ↔ last element wrap) and return focus to the opener on close (shared helper for all dialogs). |
| K5 | Playing room | The `<video>` element takes **4 tab stops** (its native play / seek / volume / fullscreen) with no focus ring of ours. | Acceptable (native controls); give the video a visible `:focus-visible` outline so the first stop is seen. |
| K6 | First tips (empty room, first visit) | The tips are `role="dialog"` with no name and come **after the footer** in tab order; "Next" / "Close" can't be reached early. | Give each tip `aria-label` ("Tip 1 of 3: Invite"), move focus to its "Next" when it opens, Esc already ends them. |
| K7 | Every focusable element walked | Focus ring visible on all of them (no element without a ring, apart from the native video). | — (keep it). |

## Screen-reader names and roles (axe)
| # | Where | axe rule (impact) | What | Suggested fix |
|---|---|---|---|---|
| S1 | Games hall `#game-menu` | aria-required-children (critical) | `role="menu"` but its items are inside wrappers / headings, not direct `menuitem` children. | Use `role="dialog"` + `aria-label="Game hall"` with normal buttons (it is a panel, not a menu), or make the groups `role="group"` with `menuitem` children. |
| S2 | XOX board `#xox-board` | aria-required-children / aria-required-parent (critical, 9) | `role="grid"` with `gridcell` buttons but no `row`s. Cells are named "square 1" … with no state. | Drop the grid roles (plain buttons in a `group` named "Board") and name each cell with its state: "Row 1, column 1, empty" / "…, X". Same check for Connect Four's columns ("Column 3, 2 free"). |
| S3 | First tips | aria-dialog-name (serious) | See K6. | `aria-label` per tip. |
| S4 | Chat list | aria-allowed-role (minor) + listitem (serious) | `<ul role="log">` holds an `<li class="chat-empty">`; with the log role, list items are no longer valid. | Keep `role="log"` on a `div`, or keep the `ul` and put `role="log"` on its wrapper; the empty note as a `p` outside the list. |
| S5 | Theme strip (home) | aria-allowed-role (minor) | `<nav role="radiogroup">`. | Use a `div role="radiogroup" aria-label="Theme"` (nav is for navigation). |
| S6 | Join card, room | page-has-heading-one (moderate) | No `h1` on the join card and in the room. | Join: the room name as `h1`; room: a visually hidden `h1` with the room name. |
| S7 | ⋯ More, games hall | region (moderate) | Popovers appended to `body` outside landmarks. | Mount them inside `main` (or give the popover `role="dialog"` with a name). |
| S8 | Voice buttons (`#voice-mic` "Mute", 🎙 / 📷 on the rail) | — (manual) | Toggles have no `aria-pressed`; the name flips ("Mute" / "Unmute") which works, but the off state is shown mainly by **red**. The icons do carry a slash, so it is not colour-only, but the red reads as an error (sweep 1). | Add `aria-pressed` to mic / camera toggles; keep the slashed icon; use a neutral "off" colour (grey) and keep red for real errors. |

## Reduced motion
With `prefers-reduced-motion: reduce` no infinite animation runs on the home page or in the room, and the drifting
`body::before` aura is off. Good. Still to check by hand: the intro (new Sidelit intro has its own still frame,
`intro/README.md`), flying emojis (they should fade in place), the countdown.

## Suggested order for the card
K2 (rail by keyboard) → K1 (tab order + skip link) → K4 (dialog focus trap + return) → K3 (menu pattern) → S1 / S2
(game roles and cell names) → C1 (accent) → the rest. Add an axe run to a harness (it needs `bypassCSP` in Playwright,
because our CSP rightly blocks injected scripts) so new violations fail CI.
