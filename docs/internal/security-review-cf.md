## Summary (5 lines)

1. The code follows most Cloudflare rules well: capped body reads everywhere, Origin checks, rate-limit bindings, SQLite DOs, Hibernation API, alarms instead of timers for durable work, secrets step-scoped in a `production` environment, SHA-pinned actions.
2. The main open risk is **account-wide Free-plan Durable Object quotas** (100 k rows written, 100 k requests, 13 000 GB-s a day): one anonymous client can spend them in minutes through **WebSocket messages**, which no WAF / edge rule can see, so the whole site stops until 00:00 UTC (CF-1, High).
3. The HTTP fallback keeps objects awake (held polls are billed duration) and costs 1 DO request + 1 Worker request per message, so one address can hold ~400 objects awake and legit hotspot users cost 20–30× a WebSocket user (CF-2, Medium).
4. Rooms have no per-address cap on connections: one script can fill any room whose id it knows (50 seats) and come back after a kick with a new browser id (CF-3, Medium).
5. Smaller items: heavy room constructor on every wake (carried over), the image budget vs the 5 GB storage cap, timer-driven floating promises, no top-level error handling, observability / log-content check, stale generated types.

## Good practices already in place

- **Bodies:** every body a Worker route or object reads is streamed with a cap (`readCapped`, `fallback.ts:327`); `unsave` refuses missing / > 1 KB lengths at the edge (`index.ts:215-222`); fallback `send` ≤ 1.1 MB, per-session / per-object memory budgets (`fallback.ts:32-43`). No `request.json()` on incoming requests.
- **Origin / routing:** Origin checks on every browser route (`allowedOrigin`, feedback and lab require one); ids checked by pattern before any object wakes; fallback `sid` checked in the Worker; internal headers set or stripped by the Worker for socket routes (`index.ts:70-71`, `96`, `100-101`).
- **Rate limits:** Workers rate-limit bindings per IP hash for connects, search, info / version / probe / usage / lab, feedback, fallback; daily YouTube unit budget and per-IP share; cross-room image byte budget (`UploadGate`); feedback hourly / daily gate; the in-object `RateLimiter` map is capped (4000 keys).
- **Secrets:** only in `env`, never logged or echoed; uploaded with `--secrets-file` from `$RUNNER_TEMP`; only the deploy step sees them, with a guard step; deploy in the `production` environment; `USAGE_TOKEN` and `LAB_CODE` compared on hashes in constant time; IP hash is an HMAC with a daily random key; only the *resolved* key is cached across requests (R4-2).
- **Randomness:** `crypto.randomUUID()` / `getRandomValues` for ids, sids, tokens, dice, poker deck, fleets (the only `Math.random` uses are quiz question order and draw word picks: not security-relevant).
- **Durable Objects:** all classes SQLite-backed (migrations v1–v12); Hibernation API (`acceptWebSocket`) everywhere except the short probe / turn-away sockets; one alarm per object that covers all durable timers, fallback sweeps in the alarm (BH8), ghost checks via attachments; empty rooms / tables `deleteAll()` after their TTL; every list stored is capped; recap counters coalesced (PERF1e); lab powers only with a `--var` flag **and** a localhost URL.
- **Worker:** `satisfies ExportedHandler<Env>`; cron work tied to `ctx.waitUntil` with a catch (`index.ts:117`); outbound calls have `AbortSignal.timeout`; `/api/*` answers get `nosniff` + `no-store` (`withApiHeaders`); Cache API hits are marked (`X-SWM-Cache`) and tested live; podcast feeds parsed with a bounded reader (CPU on Free).
- **Cron:** 1 of 5 Free cron triggers; in-process checks; ≤ 2 GitHub calls a run with a timeout; well inside the 15 min / 10 ms CPU limits (docs: cron duration 15 min, Free CPU 10 ms).
- **CI / supply chain:** workflow token `contents: read`, `contents: write` only on the tag job, `pull_request` (not `_target`), actions pinned by SHA, lockfile pins wrangler 4.157.0 / workerd 1.20261103.1, Dependabot for npm + Actions.
- **Headers:** strict CSP for static assets (`_headers`), no inline scripts, `object-src 'none'`, `base-uri 'none'`, `Permissions-Policy`; Version URLs are not generated for Workers with Durable Objects (docs), so old versions are not reachable by URL.
- **Config:** `wrangler.jsonc`, recent `compatibility_date` (2026-09-01; schedule a bump), no `nodejs_compat` needed (no `node:` imports).

## Notes and limits of this audit

- Free-plan numbers used: DO requests 100 000/day (WS messages 20:1), duration 13 000 GB-s/day, rows read 5 M/day, rows written 100 000/day, storage 5 GB, Worker CPU 10 ms, cron CPU 10 ms / duration 15 min — all from `cloudflare-docs` sources fetched 8 Nov 2026 (`durable-objects/platform/pricing`, `…/limits`, `workers/platform/limits`). The attack timings in CF-1 / CF-2 are arithmetic from those numbers and the code's limits, not measurements; the exact behaviour of an object whose write fails after the quota (reset vs error) is marked to verify.
